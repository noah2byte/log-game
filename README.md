# 로그: 열두 시진의 문

한국 삼국 시대 × 현대 × 연옥 세계관의 2D 횡스크롤 픽셀 액션 플랫포머다.
탐정 로그가 열두 시진의 문을 지키는 십이지신을 넘어, 빼앗긴 달토끼를 되찾는다.

- 세계관 정리: `docs/worldbuilding.md` 참고
- 브라우저에서 바로 돌아가며, 빌드 결과물은 정적 파일이라 GitHub Pages에 그대로 올릴 수 있다.

---

## 실행

```bash
npm install
npm run dev            # 개발 서버 (http://localhost:5173)
npm run build          # 타입 검사 후 dist/ 에 배포용 빌드
npm run build:single   # 에셋까지 HTML 한 파일에 넣은 미리보기용 빌드 (dist-single/)
npm run typecheck      # 타입 검사만
npm run format         # Prettier 정리
```

`?debug`를 붙여 열면 테스트용 기능이 켜진다.

| 키 | 기능 |
|---|---|
| `1`~`9`, `0`, `-`, `=` | 제1문~제12문으로 바로 이동 (넋·무기도 그 단계에 맞춰 준다) |
| `]` | 현재 스테이지의 보스 방 앞으로 이동 |
| `D` | 판정 박스 보기 |
| `H` | 피격 모션 테스트 |

디버그 모드에서는 `window.__game`으로 상태(`$`)와 몇몇 함수를 콘솔에서 만질 수 있다. 자동 테스트(Playwright)도 이걸 쓴다.

## 배포

이 게임은 블로그 저장소와 **별도 저장소**로 두고, 그 저장소의 GitHub Pages로 배포한 뒤 블로그 게임 탭에서 링크한다. 블로그 저장소에 빌드 결과를 복사해 넣으면 게임을 고칠 때마다 해시가 붙은 이미지 파일이 블로그 이력에 쌓이고, 글 이력과 게임 이력이 섞여 관리가 번거로워지기 때문이다.

### 처음 한 번

1. GitHub에 `log-game` 저장소를 만들고 이 프로젝트를 올린다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 바꾼다.
3. `main`에 푸시하면 `.github/workflows/deploy.yml`이 타입 검사 → 빌드 → 배포를 한다. 주소는 `https://noah2byte.github.io/log-game/`가 된다.

`vite.config.ts`에서 `base: './'`로 두어서, 저장소 이름이 바뀌거나 하위 경로에 올려도 에셋 경로를 고칠 필요가 없다.

### 블로그 게임 탭에 연결

블로그의 게임 탭은 `_data/games.yml`에 항목만 추가하면 카드가 생기고, 카드를 누르면 탭 안의 플레이어(iframe)에서 게임이 열린다. 블로그 서비스 워커는 같은 파일에서 게임 경로를 읽어 캐시에서 제외하므로 따로 고칠 필요가 없다.

```yaml
- title: 로그 — 열두 시진의 문
  url: https://noah2byte.github.io/log-game/
  ...
```

다른 곳에 직접 넣고 싶으면 iframe을 쓴다.

```html
<iframe src="https://noah2byte.github.io/log-game/" width="100%" style="aspect-ratio:16/10;border:0" allow="autoplay" loading="lazy"></iframe>
```

iframe 안에서 열리면 제목·설명을 숨기고 게임 화면만 보이게 자동으로 바뀐다. 블로그와 게임이 같은 도메인(noah2byte.github.io)이라 localStorage를 함께 쓰지만, 저장 키에 `log-12gates-` 접두어를 붙여서 블로그나 다른 게임의 데이터와 겹치지 않는다.

### 블로그 저장소에 직접 넣고 싶다면

`./scripts/deploy-to-blog.sh ../noah2byte.github.io game/log`로 빌드 결과를 복사할 수도 있다. 위 이유로 권장하지는 않는다.

### 용량을 줄인 방법

- 스프라이트와 일러스트를 **WebP**로 바꿨다. 같은 화질에서 5.8MB가 2.1MB가 됐다. 스프라이트 변환 도구도 처음부터 WebP로 저장한다.
- **스테이지별로 필요한 스프라이트만 먼저** 받는다. 첫 화면은 제1문 요괴와 도입 영상에 나오는 토끼만 받고 바로 뜨며, 나머지는 타이틀과 플레이 중에 뒤에서 하나씩 받는다. 아직 못 받은 스테이지로 넘어가면 짧은 로딩 화면을 보여준다.
- 첫 로딩 중에는 진행 막대를 보여준다.

## 설계 결정과 이유

### Vite + TypeScript, 게임 엔진은 쓰지 않았다

Phaser 같은 게임 엔진으로 옮기는 것도 검토했다. 하지만 PoC에서 이미 물리, 판정, 스프라이트 외곽선, 컷신까지 직접 만든 엔진이 돌아가고 있었고, 엔진으로 옮기면 사실상 전부 다시 짜야 해서 그 과정에서 지금의 손맛(점프 높이, 넋날 판정 등)이 달라질 위험이 컸다. 대신 코드 관리를 어렵게 만들던 진짜 원인, 즉 **1,400줄짜리 HTML 한 파일**과 **에셋이 base64로 박혀 있는 구조**를 해결하는 데 집중했다. Vite는 모듈 번들링, 개발 서버, 에셋 해시·배포 빌드를 맡고, TypeScript는 점진적으로 타입을 붙여가는 발판이 된다.

### 공유 상태는 `core/state.ts`의 `$` 하나로 모았다

PoC는 전역 변수 수십 개를 여러 함수가 함께 읽고 썼다. ES 모듈에서는 다른 모듈의 `let` 변수에 직접 대입할 수 없어서, 가변 상태를 한 객체에 모으고 `$.p`, `$.enemies`처럼 접근하게 바꿨다. 상태가 한곳에 있으면 저장·디버그·테스트에서 들여다보기도 쉽다.

### 옮겨온 모듈에는 `// @ts-nocheck`가 붙어 있다

PoC 코드를 모듈로 나눈 첫 단계라, 동작을 바꾸지 않는 것을 최우선으로 했다. 한 번에 엄격한 타입을 붙이면 수백 군데를 고치다 버그가 섞이기 쉽다. 새로 짠 `main.ts`, `core/assets.ts`는 이미 `strict` 타입이 적용되어 있고, 나머지는 파일 단위로 `@ts-nocheck`를 떼면서 타입을 붙여가면 된다. `data/` 폴더부터 시작하는 걸 추천한다. 데이터 구조가 타입으로 정해지면 나머지가 따라오기 쉽기 때문이다.

### 보스 여덟은 데이터로 정의한다

`data/enemies.ts`의 `GB`에 동작 종류(근접, 돌진, 도약, 투사체, 낙뢰, 소환)와 시간·범위·판정 크기만 적으면 `bosses/generic.ts`가 알아서 돌린다. 난이도 조절이 숫자 수정만으로 끝나고, 새 보스를 추가할 때도 코드를 거의 건드리지 않는다. 쥐·소·호랑이·토끼는 분열, 벽 기절, 창귀 소환, 정화처럼 이야기와 묶인 고유 규칙이 있어서 전용 파일로 뒀다.

### 스테이지는 시드 고정 생성, 첫 스테이지만 손으로 배치

제1문은 튜토리얼 역할이라 요괴 배치를 손으로 짰다. 제2문부터는 `world/stages.ts`의 `genStage`가 스테이지 번호를 시드로 지형·발판·요괴·체크포인트를 만든다. 시드가 고정이라 **매번 같은 맵**이 나온다. 무작위로 매번 바뀌면 "이 구간 어렵다"는 피드백을 재현할 수 없어서다. 각 스테이지는 `data/stages.ts`의 `pool`에 적힌 요괴 위주로 채워지고, 스테이지가 오를수록 요괴 수와 속도(`DIFF`)가 올라간다. 연옥의 하루가 흘러가는 느낌을 주려고 스테이지마다 하늘 색조(`tint`)도 다르게 했다.

### 스테이지마다 다른 테마

`world/themes.ts`에 열두 테마를 정의했다. 테마 하나가 배경 네 겹(하늘·먼 풍경·중간·가까운 풍경), 바닥 질감, 대기 입자, 화면 연출, 지형 생성 규칙을 함께 가진다. 배경만 바뀌고 지형이 같으면 금방 단조로워지기 때문에, 보이는 것과 밟는 것을 한 묶음으로 설계했다.

| 문 | 테마 | 지형의 특징 |
|---|---|---|
| 자시 | 가라앉은 도시 | 기본 지형 |
| 축시 | 쇳물이 흐르는 제철소 | 층층이 쌓인 철골 발판, 쇠 발판(불가사리), 장애물 |
| 인시 | 대숲 산성 | 높낮이가 다른 계단식 언덕, 바위 |
| 묘시 | 달의 정원 | 연못 위 징검돌 |
| 사시 | 서낭당 늪 | 물웅덩이, 징검돌, 움직이는 발판 |
| 오시 | 성벽 아래 벌판 | 길게 달리는 평지와 넘어야 할 울타리 |
| 미시 | 구름 위 산사 | 높이가 제각각인 구름 섬, 움직이는 구름 |
| 신시 | 남사당 장터 | 차양 발판, 줄타기 |
| 유시 | 노을 송신탑 | 높이 쌓인 탑 발판 |
| 술시 | 순라길 성곽 | 높은 성벽 구간과 바리케이드, 탐조등 |
| 해시 | 황금 곳간 | 금화 계단 |
| 진시 | 폭풍의 용궁 | 조각난 섬, 움직이는 발판, 번개 |

하늘 색은 열두 시진의 흐름을 따른다. 자시·축시의 깊은 밤, 인시의 새벽 직전, 묘시의 새벽, 오시의 한낮, 유시의 노을, 술시·해시의 밤, 마지막 진시의 폭풍이다. 스테이지를 넘길 때마다 연옥의 하루가 흐른다는 걸 색으로 느끼게 하려는 것이다.

배경은 480×270 캔버스에 그려 두 배로 키운다. 해상도를 낮게 그려야 스프라이트와 같은 픽셀 아트 질감이 나오기 때문이다. 한 번 그린 배경은 캐시해서 스테이지를 다시 시작해도 다시 그리지 않는다.

새 테마를 만들 땐 `THEMES[i]`의 `gen` 값만 바꿔도 지형 성격이 크게 달라진다. `stepping`(징검돌), `moving`(움직이는 발판), `ropes`(줄타기), `towers`(층층 발판), `stairs`(계단), `hurdles`(장애물), `heights`(땅 높이 후보)를 조합하면 된다.

### 발판은 로그의 몸 크기에서 역산한 규칙으로만 놓는다

로그의 키는 78px, 점프 최고 높이는 약 125px다. 다만 125는 점프 키를 끝까지 누르고 있을 때의 이론값이라, 실제로 편하게 오르는 높이는 그보다 낮다. 처음엔 이론값에 가깝게 잡았다가 인시에서 올라설 수 없는 발판이 생겨 진행이 막혔고, 다음 규칙으로 다시 맞췄다.

- 발판 윗면은 땅에서 **100px 이내**(점프 최고 높이의 80%). 누구나 편하게 올라설 수 있어야 해서다.
- 발판 아랫면은 땅에서 **84px 이상**. 밑으로 걸어서 지나갈 수 있어야 해서다. 두 조건을 동시에 만족하려고 발판 두께를 24px에서 12px로 줄였다.
- 층층 발판은 **100px 간격**.
- 이웃한 땅의 높이 차는 **40px 이하**, 구덩이 폭은 이론상 건널 수 있는 거리의 **75%까지만**. 최고 속도로 가장자리 끝에서 뛰어야만 닿는 구덩이는 사실상 못 건너는 구덩이다.
- **점프가 필요한 곳 위에는 발판을 두지 않는다.** 발판 아랫면이 로그 머리 바로 위에 있어서, 그 밑에서는 점프할 공간이 없다. 구덩이 가장자리나 장애물 위에 발판이 있으면 점프하다 머리를 부딪혀 떨어진다. 그래서 발판은 평평한 땅 한가운데(가장자리에서 150px 이상)에만 두고, 장애물은 구덩이 가장자리에서 200px 이상 떨어뜨린다.
- 줄타기는 뺐다. 구덩이 위에 걸면 구덩이를 건너는 로그의 머리에 걸리기 때문이다.
- 마지막 땅 조각은 보스 방까지 이어져 있어서, 장애물과 금화 더미가 보스 방 안에 생기지 않게 따로 막는다.

이 규칙으로 바꾼 뒤 열두 스테이지의 모든 구덩이(63곳)를 실제 입력으로 뛰어 건너는 자동 테스트를 돌려 전부 통과했다.

### 물리는 1/120초 고정 간격

`main.ts`에서 화면 갱신과 물리 갱신을 분리했다. 60Hz 모니터와 144Hz 모니터에서 점프 높이나 판정이 달라지면 안 되기 때문이다.

### 에셋은 `import.meta.glob`으로 불러온다

`src/assets/sprites/`에 WebP를 넣으면 코드 수정 없이 자동으로 포함된다. 일반 빌드에서는 해시가 붙은 개별 파일로 나가서 브라우저 캐시가 잘 먹고, `build:single`에서는 같은 코드가 data URI로 인라인되어 한 파일짜리 미리보기가 된다.

### 저장

`localStorage`에 도달한 스테이지, 넋 수, 무기, 모은 기억 조각 수를 저장한다. 스테이지를 시작할 때와 보스를 쓰러뜨린 직후에 저장한다. 보스를 잡고 문을 지나기 전에 창을 닫아도 다음 스테이지부터 이어가게 하려는 것이다. 타이틀에서 "이어하기"로 불러온다. `R`(문 처음부터)은 그 스테이지를 시작할 때의 넋·무기로 되돌린다. 재시작으로 넋을 불려 나가는 걸 막기 위해서다.

### 소리

효과음은 오픈소스 [ZzFX](https://github.com/KilledByAPixel/ZzFX)(MIT)로 코드에서 합성한다. 음원 파일이 없어서 용량이 늘지 않고, 숫자 배열만 바꾸면 소리를 다듬을 수 있다. 배경음은 Web Audio로 낮은 드론 위에 평조 5음 음계(궁·상·각·치·우에 해당하는 음정)를 무작위로 뜯는 생성형 음악이다. 국악 느낌을 음원 없이 내려는 선택이다. 보스전에서는 템포가 빨라지고 북소리가 섞인다. `M`으로 끄고 켤 수 있고 설정은 저장된다.

## 콘텐츠 추가하기

### 새 스프라이트

```bash
python3 tools/sprite_pipeline.py 받은시트.png --name 이름
```

마젠타 배경을 반투명 경계까지 고려해 지우고, 캐릭터 덩어리를 찾아 행·열 순서로 프레임을 만든 뒤 `src/assets/sprites/이름.webp`와 `sprites.json`을 갱신한다. 이웃 프레임과 창·채찍 같은 게 붙어서 하나로 잡히면 `--split 6:y:569`처럼 나눌 위치를 지정한다. 출력되는 프레임 번호를 보고 `data/enemies.ts`의 `FA`에 동작별 프레임을 적으면 된다.

제미나이에 시트를 요청할 때 지킬 규칙은 이렇다. 배경은 단색 마젠타(#FF00FF), 캐릭터에는 분홍·마젠타 금지, 빛 번짐·그림자·글자 금지, 원본 로그 이미지 첨부. 분홍이 있으면 배경과 함께 지워지고, 빛 번짐은 배경 제거 후 지저분하게 남기 때문이다.

### 그림 배경 넣기

스테이지마다 그림 두 장을 받는다. 하늘과 먼 풍경을 담은 불투명한 `back`, 중간·가까운 풍경을 마젠타 배경 위에 그린 `front`다.

```bash
python3 tools/bg_pipeline.py 뒤.png --stage 2 --layer back
python3 tools/bg_pipeline.py 앞.png --stage 2 --layer front
```

`src/assets/bg/stage02/`에 들어가면 코드 수정 없이 그 스테이지 배경이 그림으로 바뀐다. 파일이 없는 스테이지는 코드로 그린 테마 배경을 그대로 쓴다. 한 번에 열두 스테이지를 다 준비하지 않아도 되게 하려는 것이다. 도구가 좌우 끝을 섞어 이음매를 없애고 높이를 540px로 맞춘다. 레이어를 네 겹이 아니라 두 겹으로 한 건, 스테이지마다 그림 네 장을 받는 건 부담이 크고 두 겹만으로도 앞뒤가 다른 속도로 흘러 깊이감이 충분히 나기 때문이다.

### 새 요괴

1. 스프라이트를 위 도구로 넣는다.
2. `data/enemies.ts`의 `ET`(크기·체력·속도), `FA`(애니메이션), `NAMES`(퇴치 문구)에 항목을 추가한다.
3. `entities/enemies.ts`의 `updateEnemies`에 행동을 추가한다.
4. `data/stages.ts`의 원하는 스테이지 `pool`에 넣는다.

### 보스 난이도 조절

`data/enemies.ts`의 `GB`에서 조절한다. `tw`(예고 시간)를 줄이면 반응하기 어려워지고, `cd`(다음 공격까지 간격)를 줄이면 몰아친다. `nE`는 체력 절반 이하일 때의 투사체·낙뢰 수다. 체력은 `ET`의 `hp`다.

## 조작

| 키 | 기능 |
|---|---|
| ← → | 이동 |
| Space / ↑ | 점프 (길게 누르면 높이) |
| Z | 공격 |
| X | 랜턴 |

| M | 소리 켜기·끄기 |
| Esc | 타이틀로 (컷신 중에는 건너뛰기) |

### 모바일

손가락이 주 입력인 기기에서는 터치 버튼이 자동으로 나타난다.

- **가로 화면**: 버튼이 게임 화면 위 양쪽 아래에 반투명하게 겹친다. 왼손은 방향, 오른손은 점프·베기·랜턴·무기다. 휴대용 게임기와 같은 배치라 손이 익숙하고, 캐릭터가 서는 높이를 가리지 않도록 버튼을 바닥 쪽으로 낮게 뒀다.
- **세로 화면**: 게임 화면이 작아 버튼을 겹치면 화면을 가리므로, 화면 아래에 큰 버튼으로 둔다. "가로로 돌리면 화면이 커진다"는 안내가 뜬다.
- 방향 버튼은 한 영역에서 손가락 위치로 좌우를 판단한다. 손가락을 미끄러뜨려 방향을 바꿔도 입력이 끊기지 않게 하려는 것이다.
- 여러 손가락을 동시에 추적해서, 달리면서 점프하고 벨 수 있다.
- 위쪽 가운데에 전체 화면(지원하는 브라우저만, 가로 고정 포함), 소리, 타이틀 버튼이 있다.
- 두 손가락 확대, 길게 눌렀을 때의 메뉴, 화면 끌어당김 새로고침을 막았다. 게임 중 실수로 화면이 움직이지 않게 하려는 것이다.
- 타이틀과 컷신에서는 버튼을 숨긴다. 화면을 눌러 진행해야 하기 때문이다.

## 알려진 한계와 다음 단계

- **타입**: 옮겨온 모듈의 `@ts-nocheck`를 파일 단위로 떼며 타입을 붙여야 한다.
- **도깨비불·그림자 잡귀**: 아직 코드로 그린 임시 그림이다. 스프라이트를 받으면 위 절차로 교체한다.

- **폰트**: Google Fonts(고운바탕·고운돋움, OFL)를 외부에서 불러온다. 오프라인 배포가 필요하면 폰트 파일을 저장소에 포함한다.
